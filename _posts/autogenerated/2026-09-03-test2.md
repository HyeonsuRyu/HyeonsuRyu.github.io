# 시스템 구축 개요

단순히 마크다운(Markdown) 파일을 저장하는 단계를 넘어, 드디어 나만의 **PKM(Personal Knowledge Management) 시스템**의 기반을 완성했습니다. 

이번 시스템 구축의 핵심은 단순히 기록을 쌓아두는 것에 그치지 않고, **LLM(Large Language Model)과 RAG(Retrieval-Augmented Generation)를 연동**하며, 작성된 메모가 블로그로 배포되기까지의 전 과정을 **100% 자동화**하는 구조를 만드는 데 있습니다.

이번 프로젝트의 핵심 목표는 다음과 같습니다.

* **데이터의 분리**: 개인적인 기록을 위한 'Private Vault'와 대외 공개용인 'Public Vault'의 명확한 분리
* **투트랙(Dual Track) 자동 배포**: GitHub Actions를 활용하여 각 Vault의 변경 사항을 독립적으로 배포
* **HITL(Human-in-the-loop) 구조 구현**: 로컬 LLM(Ollama)을 활용하여, 가공되지 않은 날것의 메모를 정제된 블로그 포스트로 변환하는 프로세스 구축

## 구현 과정에서의 도전 과제

시스템을 구축하는 과정에서 몇 가지 기술적인 허들이 있었습니다.

### 1. 권한 및 설정 문제
GitHub Actions를 활용한 자동 배포 과정에서 **Fine-grained PAT(Personal Access Token)**의 권한 설정 문제와, Jekyll 블로그 특유의 파일명 규칙(파일명에 공백이나 특수문자 제한 등)을 맞추는 작업에 꽤 많은 시간을 할애했습니다.

### 2. 마크다운 포맷 변환
옵시디언(Obsidian)에서 사용하는 **위키링크(WikiLinks) 형식의 이미지 경로**를 Jekyll이 인식할 수 있는 표준 마크다운 포맷으로 변환하는 작업이 필수적이었습니다. 이를 위해 정규표현식(Regex)을 활용한 변환 로직을 구현하여 배포 파이프라인에 포함시켰습니다.

## 마치며

초기 세팅 과정은 까다로웠지만, 일단 파이프라인이 완성되고 나니 작업 경험이 매우 쾌적해졌습니다. 이제 옵시디언에서 글을 작성하고 `push`하기만 하면, 백그라운드에서 LLM이 글을 정제하고 자동으로 Pull Request(PR)까지 생성해 줍니다.

이러한 자동화된 워크플로우 덕분에 기록에 대한 심리적 허들이 낮아졌습니다. 앞으로 이 시스템을 활용해 학습한 내용과 다양한 생각들을 부담 없이, 그리고 꾸준히 정리해 나갈 계획입니다.
