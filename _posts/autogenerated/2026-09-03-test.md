# [Project] LLM과 GitHub Actions를 활용한 자동화된 PKM 시스템 구축기

단순히 메모를 쌓아두는 것을 넘어, 기록이 가치가 되는 시스템을 고민해 왔습니다. 드디어 마크다운 파일을 저장하는 수준을 넘어, **LLM과 RAG를 연동하고 블로그 배포까지 100% 자동화하는 나만의 PKM(Personal Knowledge Management) 시스템**의 기반을 구축했습니다.

## 🚀 핵심 목표

이번 시스템 구축의 핵심은 '기록의 효율성'과 '공개 범위의 제어'입니다. 이를 위해 다음과 같은 세 가지 목표를 설정했습니다.

*   **Private & Public Vault의 분리**: 개인적인 아이디어와 지식은 안전하게 보관하되, 정제된 콘텐츠만 외부에 공개할 수 있도록 구조를 분리했습니다.
*   **GitHub Actions를 이용한 Dual-Track 배포**: 별도의 수동 작업 없이, GitHub Actions를 통해 프라이빗과 퍼블릭 저장소로 각각 자동 배포되는 파이프라인을 구축했습니다.
*   **Local LLM(Ollama) 기반의 콘텐츠 정제 (HITL 구조)**: 로컬 환경의 Ollama를 활용하여, 날것(Raw)의 메모를 블로그 포스트로 정제하는 프로세스를 만들었습니다. 이는 인간이 개입하여 검토하는 **HITL(Human-in-the-loop)** 구조를 지향합니다.

## 🛠️ 구현 과정에서의 도전 과제

시스템을 구축하는 과정이 순탄치만은 않았습니다. 특히 자동화 파이프라인을 정교하게 만들기 위해 다음과 같은 기술적 문제들을 해결해야 했습니다.

1.  **GitHub Actions 권한 관리**: Fine-grained PAT(Personal Access Token)를 설정하며 권한 범위를 최소화하면서도 자동 배포가 원활히 이루어 있도록 세밀한 조정이 필요했습니다.
2.  **Jekyll 파일명 규칙 준수**: Jekyll 엔진의 특성상 파일명에 제약이 많습니다. 이를 자동화 과정에서 충돌 없이 처리하는 로직을 구현했습니다.
3.  **WikiLink를 표준 마크다운 포맷으로 변환**: 옵시디언(Obsidian) 특유의 이미지 위키링크(`[[image.png]]`) 형식을 표준 마크다운 이미지 문법으로 변환하기 위해 정규표현식(Regex) 처리를 적용했습니다.

## 💡 마치며

파이프라인 구축을 완료하고 나니, 개발자로서 매우 쾌적한 경험(Developer Experience)을 누릴 수 있게 되었습니다. 이제 옵시디언에서 자유롭게 글을 쓰고 `push`하기만 하면, 백그라운드에서 LLM이 글을 정제하고 자동으로 Pull Request(PR)까지 생성해 줍니다.

이 시스템은 앞으로 제가 학습한 내용과 깊은 생각들을 부담 없이, 그리고 꾸준히 기록해 나갈 수 있는 든든한 기반이 될 것입니다. 앞으로 이 시스템을 통해 발전해 나갈 기록들을 기대해 주세요!
